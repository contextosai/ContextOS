# ContextOS 0.1.0-alpha.23

The twenty-third alpha of ContextOS completes the agent governance work begun in
alpha.22. It adds what an operator, a finance owner, a security reviewer and an
auditor each need beyond deciding a single tool call:

- a governance view and incident cases;
- spend that is capped and attributable across runs;
- tools and packs that cannot change underneath a deployment;
- evidence a reviewer can verify without installing anything.

As before, every addition extends an existing mechanism and none weakens a core
guarantee:

- authorization before the action;
- shared limits across agents and runs;
- held effects on unknown outcomes;
- signed, hash-chained evidence verifiable offline;
- digest-bound approvals;
- tenant isolation;
- fail-closed behaviour.

Each addition has a threat-model entry (T59 to T72) and regression tests.

## What changed since 0.1.0-alpha.22

**Observability and assurance**

- A governance dashboard on Tower's Posture page and at `GET /api/dashboard`. It shows held effects, refusals by reason, approvals waiting, shared ceilings near their limit (read live from each runtime), policy drift, active waivers, unreviewed break-glass grants and evidence-chain health.
- Incident cases in Tower: opened from a denial, hold, finding or anomaly, with a timeline, linked audit entries, an owner and a status. A case exports as a report with a recorded digest.
- Behaviour flags: Tower findings when an agent with at least a week of history uses a new tool, a new model, or an hour of the day it has not used in two weeks. They create reviews and never block.
- Evaluation-gated releases. An independent evaluator records suite results on an `agent_release` (`POST /v1/agent-releases/evaluations`). With `[guards.release_evaluations]`, a covered agent's runs are admitted only once every required suite passed on that exact release. A failure recorded later stops it again.

**Cost**

- Model allow-lists, global and per agent (`[guards.models]`). They are checked against a run's pinned model at admission, and against the model a metering gateway names when it claims a call, before the call goes out.
- Usage ceilings across runs (`[[guards.usage_ceilings]]`): model tokens or spend per agent or per tenant per window. Holds use the shared-guarantee ledger, so concurrent reservations cannot pass a ceiling together. The ceiling counts what calls reserve, not measured usage above it (see Known limits).
- Chargeback. Tower groups spend by business unit, owner and tenant, and exports CSV. `ctx chargeback` builds the same rows offline from a verified export. Measured, self-reported and uncovered usage stay apart.

**Supply chain**

- Quarantine for drifted upstream tools. A capability whose pinned MCP tool changed stays refused, even if the server changes it back, on every replica and across restarts. It is lifted by a reviewed re-pin, or by an audited operator release that is refused while the tool still differs. Tower raises `tool_quarantined`.
- Signed packs. `ctx pack-sign` writes a detached Ed25519 signature over a pack's canonical digest. With `[pack_signing]`, unsigned, forged or untrusted packs are not loaded, and `pack_loaded` records the signer.
- Every release asset (archives, SBOMs, wheels, the npm tarball) now carries a keyless Sigstore bundle. The bundle is verified in the release job before the draft exists; [Verify a release](https://github.com/contextosai/ContextOS/blob/v0.1.0-alpha.23/docs/VERIFY_RELEASE.md) gives the commands. A weekly and per-tag workflow rebuilds the binaries from two paths and compares digests, and advisories are re-checked daily.

**Compliance and evidence**

- Every control in `docs/COMPLIANCE.md` and the evidence pack states its coverage: `covered`, `partial` (naming what is missing) or `organizational`. SOC 2 has its own section in the docs, and the pack adds `--framework nist-ai-rmf`. The mapping is not a certification.
- `ctx audit-pack`: one signed folder for an auditor. It holds:
  - the evidence pack, inventory and approvals;
  - the packs in force and the configuration's digest;
  - a manifest signed with Ed25519;
  - a `verify.py` that checks it with Python's standard library, against a key the auditor supplies.

**Interoperability**

- SIEM formats for audit sinks: `splunk_hec`, `datadog` and `elastic_bulk`, with the credential in `token_env`. Masking, ordering and retries are unchanged. Elasticsearch deduplicates by tenant and sequence, and a bulk reply with a failed item is retried.
- `gen_ai_client_operation_duration_seconds`, the OpenTelemetry GenAI conventions' operation duration for governed tool calls.
- A guide to integrating a framework that has no guide yet, with four scenarios to run before calling it done.

**Fixes**

- `ctx inventory` kept only an export's last run while folding, so earlier runs' activity was dropped. Every run is now kept.

## Upgrading

- **Tool quarantine (breaking).** With `[guards] quarantine_drifted_tools` (on by default), a drifted MCP tool is no longer served again when its server rolls back. Release it with `POST /v1/upstream/quarantine/release` after review, re-pin it, or set `quarantine_drifted_tools = false`.
- **New store document kinds** (`release_evaluations`, `tool_quarantine`) are created on first use. Run `contextosd --migrate` as usual; CI checks an upgrade from an alpha.22 PostgreSQL store.
- **Rust API.** `AuditSinkConfig` gains `format` and `token_env`; `LoadedPack` and `PackIdentity` gain `signed_by`. Struct literals need the new fields. `UpstreamStatus` gains `Quarantined`, so exhaustive matches need an arm for it.
- Everything else is opt in: release evaluations, model allow-lists, usage ceilings, pack signing and SIEM formats do nothing until configured. Run `contextosd --check-config`.

## Known limits

The known limits of alpha.22 apply unchanged. In addition:

- **Usage ceilings** bound reservations, not measured usage: a hold commits at the reserved amount, and usage a metering gateway measures above a reservation is charged to the run's budget but not to the ceiling, so a caller that reserves too little can pass it. Windows are fixed, so a burst across a boundary can reach twice the limit within one window's length. A hold whose reservation is never settled counts until its window ends. Fixed after this release: measured overage counts against the ceiling, and a window is no longer refused after 1,024 calls.
- **Holds and erasure by person** cover only runs in the subject index: runs admitted after `[privacy] subject_pointers` was configured, and, in this release, about 10,000 per person (admission of further runs naming that person fails). Holds by run or tenant are not affected. Fixed after this release: the index grows in pages and each run records its own subjects.
- **Model allow-lists** stop calls only through a metering gateway that claims each call through the runtime.
- **Reproducibility** is checked for one Linux target, not every platform.
- **Sigstore signing** of release assets runs for the first time with this release.
- **Planned, not built:**
  - a timeout scenario in the Failure Lab;
  - an agentgateway ext_authz backend;
  - OPA/Cerbos policy import;
  - `ctx adapter-check`;
  - GenAI token-usage metrics, which need metering gateways to report input and output tokens separately.

  gRPC stays deferred.
