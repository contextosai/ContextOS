# ContextOS 0.1.0-alpha.18

The eighteenth alpha of ContextOS. It follows the
[enterprise problems research](../research/2026-11-08-enterprise-agent-problems.md).
That research found the strongest public evidence for agents taking consequential
actions nobody checked, not for the shared limits ContextOS led with. So this release
makes the gate in front of consequential tools easier to adopt and harder to get
wrong, and adds a way to measure it on recorded traffic before deploying it.

## What changed since 0.1.0-alpha.17

**Measure before deploying**

- `python -m contextos.replay` (Python client) replays recorded tool calls through a
  gateway against a tool server that answers with the recorded outcomes. It reports
  calls allowed, duplicates refused, limits held, approvals required, outcomes left in
  doubt, and refusals of calls that really succeeded (possible false blocks).
  `examples/replay` runs it locally.
- `docs/research/design-partner-kit.md`: who to interview, the questions, the data
  request, the scorecard, and when to stop or change direction.

**The same request, once**

- Intent keys: a capability's manifest may declare `intent.key_pointers`, the
  arguments that identify a business request. The first run to send it claims it
  tenant-wide before dispatch. The same request from another run is refused
  (`effect_repeated_across_runs`) until the claim is released or its window lapses.
  With `provider_key`, the provider's idempotency key also spans runs. Readiness
  reports consequential capabilities without one (`intent`).
- Both clients give a call that changes something and names no key an operation key
  from its capability and arguments. A re-sent call is the same operation, so a
  LangGraph node re-run on resume, or a call re-sent once approved, redeems its
  approval once.
- `contextos.integrations`: LangGraph middleware, and an OpenAI Agents SDK bridge
  whose `needs_approval` opens the gateway's own approval, so the run waits as an SDK
  interruption and can be checkpointed.

**Effects in the right place, within budget**

- `[guards.environments]`: a gateway names the environment it serves. Calls aimed at
  another (`environment_mismatch`), or whose target cannot be placed
  (`environment_unresolved`), are refused and audited; `observe` audits only.
- Startup notes capabilities named like destructive calls that are declared
  reversible or approved below `destructive`; `ctx init-tool` offers the same hint.
- Spend caps from shared guarantees: limits per agent or tenant (`resource_from`),
  estimated amounts from a price table (`amount_table`), and limits per window
  (`window_seconds`).
- `deploy/profiles`: an enforced and an observe-first starter configuration.

**Oversight on the record**

- The gateway audits `approval_requested` and `approval_redeemed`, with approvers and
  decision time. Tower's new Approvals page (`GET /api/approvals`) shows decision-time
  distributions and the share decided within ten seconds, per capability and per
  approver.
- `[guards.approval_timeout]`: an approval request nobody decides within
  `timeout_seconds` is audited (`approval_timed_out`) and escalated to a human, or,
  with `on_timeout = "deny"`, any later decision on it is refused.
- `/metrics` exports approvals requested and redeemed by capability, a decision-time
  histogram and approvals timed out.
- The workflow readiness profile (`[readiness]`) from the previous cycle ships in this
  release.

## Upgrading

- **Clients choose operation keys for unkeyed effects.** Before, each unkeyed call
  that changes something was a fresh operation. Now an identical call re-sent is the
  same operation and returns its recorded result instead of being refused as
  `effect_repeated`. Give identical calls that are distinct effects (two equal
  top-ups) keys of their own.
- **New audit entries.** `approval_requested`, `approval_redeemed`,
  `approval_timed_out`, `environment_refusal`, and `repeated_effect_refusal` with
  `effect_repeated_across_runs`. Consumers that switch on audit kinds should expect
  them.
- **The gateway records every approval request time,** not only with a review floor:
  one store write per approval request.
- The store holds new document kinds (`intent_claim`, `approval_timeouts`) and needs
  no migration. No
  configuration key, API or storage format is removed. Existing guarantee
  definitions keep their pinned digests.

## Known limits

- Estimated spend settles as estimated: the measured cost of a call is not read back.
- Model spend across runs is not capped; each run's model calls draw on its own
  budget.
- Only calls routed through the gateway are governed. An agent that holds a
  credential to the tool directly bypasses every control here; scope credentials
  first.
